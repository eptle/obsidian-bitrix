# Задание 1
>Изучите данный функционал, используя технику туров и объясните почему вы выбрали конкретные туры для этого.
#### Тур 1: _Тур коллекционера_

**Цель**: Изучить работу функционала канала с точки зрения обработки данных (например, длина сообщений, вложения, количество подписчиков).  
**Что проверяем**:

- Ограничения на длину текста сообщений.
- Форматы поддерживаемых вложений (фото, видео, документы, голосовые сообщения).
- Лимиты на количество участников в канале.

**Почему выбран**:

- Функционал новости имеет строгие ограничения на размеры данных (например, 4096 символов для текста, 2 ГБ для файлов). Эти ограничения необходимо проверить, чтобы убедиться, что приложение корректно обрабатывает данные на границах.

#### Тур 2: _Тур по плохому району_

**Цель**: Исследовать систему на наличие ошибок при некорректных или пограничных данных.  
**Что проверяем**:

- Попытка отправить сообщение длиной более 4096 символов.
- Попытка загрузить неподдерживаемый формат файла (например, `.exe`).
- Попытка опубликовать сообщение, когда у пользователя недостаточно прав (например, он не является администратором).

**Почему выбран**:

- Этот тур важен для проверки надежности системы в условиях некорректных входных данных, чтобы убедиться, что функционал корректно обрабатывает такие ситуации и не приводит к сбоям.

#### Тур 3: _Интеллектуальный тур_

**Цель**: Изучить пользовательский интерфейс и взаимодействие с функционалом.  
**Что проверяем**:

- Удобство поиска функций (например, создание и удаление сообщений).
- Отображение длинных сообщений или сообщений с большим количеством вложений.
- Реакция интерфейса при выполнении действия (например, анимация отправки сообщения).

**Почему выбран**:

- Функционал ориентирован на пользователей, и удобство интерфейса является ключевым фактором. Тур помогает выявить проблемы с доступностью или непредсказуемым поведением UI.

#### Тур 4: _Тур актера второго плана_

**Цель**: Проверить поведение канала при взаимодействии пользователей (администраторов и подписчиков).  
**Что проверяем**:

- Возможность управлять сообщениями других пользователей (например, удаление сообщений администратором).
- Уведомления, отправляемые подписчикам после публикации сообщения.
- Корректность отображения изменений статуса (например, сообщение удалено).

**Почему выбран**:

- В новостях есть функционал для взаимодействия с аудиторией, поэтому важно убедиться, что система правильно обрабатывает взаимодействия между администратором и подписчиками.

#### Тур 5: _Тур любителя ночной жизни_

**Цель**: Проверить, как система реагирует на действия, связанные со временем.  
**Что проверяем**:

- Запланированная публикация сообщений.
- Отображение времени отправки и удаления сообщений.
- Корректность сортировки сообщений по дате.
